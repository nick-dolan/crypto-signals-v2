# Правила для агентов

Строим систему раннего предупреждения, которая для каждой монеты оценивает: вероятность сильного движения в ближайшем будущем. Требуется, составить удобный набор признаков который отдадим агенту для интерпретации.

Начнётся ли заметное движение?

```
P(сильное движение в следующие 4–12 часов)
```

Признаки, с которых можно начать:

- сжатие волатильности;
- нетипичное увеличение объёма;
- ускорение Open Interest;
- рост внимания в социальных источниках;
- начало распространения narrative по нескольким монетам;
- изменение корреляции с BTC;
- аномалии ликвидаций;
- резкое изменение рыночной ширины.

Давай сюда кратенько записывать `docs/План.md`: что сделали, ближайший шаг. Простым человеческим языком, без технических деталей. Только важные шаги, а не детали!

Описание какие данные нам доступны здесь: `docs/Данные TradingView.md`

## Технические детали

- Для получения данных из TradingView используем пакет `@mathieuc/tradingview`.
- Для Fuzzy Dedupe и других операций нечёткого сравнения строк можно использовать `fuzzball`. Выбирай готовую функцию библиотеки, если она делает код проще и понятнее, чем собственная реализация.
- Для работы с датами и временем можно использовать `dayjs`. Выбирай его, если решение получается проще и понятнее, чем при использовании стандартных API JavaScript.
- Для типовых утилитарных операций можно использовать `radash`. Выбирай готовую утилиту библиотеки, если она делает код проще и понятнее, чем стандартные средства или собственная реализация.
- Используется pnpm менеджер пакетов.

## Стиль кода

- Именованные импорты записываем в одну строку, если импорт остаётся достаточно коротким и читаемым. Переносим импорт на несколько строк только тогда, когда однострочная запись становится слишком длинной или ухудшает читаемость.

## Порядок работы

- Каждый шаг делаем отдельно, обсуждаем результат, потом двигаемся дальше.
- Не пишем код без явной команды пользователя. Сначала ТОЛЬКО обсуждаем структуру/логику по пунктам, и только после утверждения и явной команды (напр. "пиши код") приступаем к реализации.
- Используй компактную разметку markdown для ответов.
- Старайся отвечать кратко, меньше текста – больше смысла.
- Главный приоритет — полное и корректное выполнение задачи, а не экономия токенов, времени или количества вызовов инструментов. При этом избегай повторения уже выполненной работы.
- Думай шаг за шагом!

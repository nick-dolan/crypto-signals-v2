# Crypto Signals v2

Система раннего предупреждения о сильных движениях криптовалют в ближайшие 4–12 часов. На основе рыночных признаков агент оценивает вероятность движения и выделяет наиболее интересные монеты. Результаты, графики, новости и публикации Twitter собраны в интерактивном HTML-отчёте.

## Справочник описаний монет

**Шаг 1.1** после отбора кандидатов дополняет `data/coin-descriptions.json` только новыми `baseCurrencyId`. Старые записи не изменяются и не удаляются, даже если монета вышла из топа. Когда новых монет нет, запросы и запись файла не выполняются.

Отдельный запуск по сохранённому результату шага 1:

```sh
pnpm exec node src/step1.1-coin-descriptions.js
```

Для каждой новой монеты агент через официальный GitHub Copilot SDK (GPT-5.6 Sol, medium) ищет источники инструментом `search_coin_sources` и читает выбранные страницы инструментом `read_coin_source`. Оба используют Tavily (`TAVILY_API_KEY` в `.env`); ключ не передаётся агенту. Приоритет — официальный сайт и документация. CoinGecko Demo API (`COINGECKO_API_KEY`) даёт вспомогательную привязку Binance USDT perpetual → проект и начальные ссылки; ошибка CoinGecko, отсутствие совпадения или пустое описание не мешают веб-исследованию. По одному тикеру проект не определяется: агент должен подтвердить его по прочитанным источникам.

На монету разрешены максимум **2 запроса поиска и 2 попытки чтения** (Tavily basic). Лимиты действуют и при параллельных вызовах инструментов, повторное успешное чтение использует кеш. Читать можно только публичные HTTP(S)-ссылки из результатов поиска или начальных данных. В справочник попадают 1–2 ссылки исключительно на успешно прочитанные страницы: агент выбирает выданные программой `sourceId`, а URL и `checkedAt` подставляет программа. Сниппеты и непрочитанные ссылки не считаются источниками; `checkedAt` означает время получения текста через Tavily, не дату обновления самой страницы.

Поисковые запросы и выбранные URL передаются Tavily, текст страниц — Copilot; это дополнительные расходы API/LLM только для новых монет. Старые записи, в том числе ранее составленные по CoinGecko, не переисследуются.

Без подтверждённой идентификации, прочитанного источника или корректного ответа агента запись не добавляется: выводится предупреждение, попытка повторяется при следующем запуске. Ошибка шага не мешает основному анализу. Повреждённый справочник не перезаписывается; успешное пополнение сохраняется атомарно. `coinCount` — размер всего справочника, `generatedAt` и `universe` — время последнего пополнения и использованный для него список, а не ограничение состава архива. HTML-отчёт автоматически читает новые записи.

## Независимый радар соседей

- **Шаг 11** — по всем загруженным монетам ищет свежий рост прямых соседей и существенно более слабую реакцию связанной монеты.
- **Шаг 12** — отдельный агент объясняет только эти расхождения, без остальных групп признаков и без вероятностей. Результат: `reports/peer-radar-YYYY-MM-DD_HH-mm-ss_GMT+3.json`, наблюдения `watch` / `limited` с точными фактами и оговорками. Выбранные агентом «Обратить внимание» (`watch`) идут первыми; остальные сохраняются.
- **Шаг 13** — HTML-отчёт с вкладками «Основной анализ» и «Радар соседей». У каждого кандидата радара — сравнительный график с его прямыми лидерами. Основной топ, оценки и графики не смешиваются с наблюдениями радара.

Отдельный запуск по сохранённым данным шагов 1–2 и справочнику `data/coin-peers.json`:

```sh
pnpm exec node src/step11-peer-radar.js && pnpm exec node src/step12-peer-radar-analysis.js
```

Шаг 11 не обращается к сети. Шаг 12 при непустом списке делает один дополнительный запрос через GitHub Copilot SDK (GPT-6-Astra, high), используя имеющуюся авторизацию; при пустом списке агент не вызывается. Сохраняются все наблюдения, а не обязательный топ-5. Это список для ручного решения, не рекомендация входа.

После готового шага 12 пересобрать HTML можно без повторного обращения к агенту:

```sh
pnpm exec node src/step13-report.js
```

Шаг 13 читает `tmp/step12-peer-radar-analysis.json`. Добавляются все наблюдения, в том числе монеты вне основного shortlist. Нужен тот же часовой срез, что у основного анализа; при наличии скана шага 11 проверяется и его версия по времени создания. Отсутствующий, повреждённый или устаревший результат заменяется понятным предупреждением, основной отчёт остаётся доступен. Пустой завершённый скан показывается отдельно от недоступных данных. Сохранённый JSON радара остаётся самостоятельным отчётом.

Графики радара работают по сохранённой истории шага 2, без запросов к сети: периоды 1/3/7 дней, кандидат и все его лидеры на одном графике, цены в процентах от общего момента. Это визуальное сравнение, не ATR-критерий сигнала. Пропуски не заполняются, отсутствие общей начальной цены отключает только соответствующую линию. Сортировка `watch` первыми действует и для ранее сохранённого ответа агента — для новых вкладок и графиков достаточно повторить шаг 13.

`pnpm all` включает оба новых шага. Ошибка радара не блокирует создание основного HTML, но отмечается ненулевым кодом запуска. Подробные критерии и формат описаны в `docs/Признаки.md`.

# Crypto Signals v2

Система раннего предупреждения о сильных движениях криптовалют в ближайшие 4–12 часов. На основе рыночных признаков агент оценивает вероятность движения и выделяет наиболее интересные монеты. Результаты, графики, новости и публикации Twitter сохраняются в Parquet, открываются в веб-интерфейсе и скачиваются автономным HTML.

## Архив и сервер отчётов

Запускать из корня проекта, в разных терминалах:

```sh
pnpm install
pnpm server
```

Список отчётов: **http://127.0.0.1:3000/**. Сервер работает независимо от пайплайна:

```sh
pnpm all
```

Авторизации нет: не публикуйте сервер в интернете без отдельной защиты доступа и HTTPS.

## Локальное превью карточки монеты

Статичная инфографика на D3 + resvg: цена, объём и Open Interest за 7 дней (168 закрытых часовых свечей), изменения цены за 4/24 часа, оценка агента. Браузер и сеть не нужны; шрифт с кириллицей включён в проект.

```sh
pnpm report:card
pnpm report:card --symbol SNX
```

По умолчанию берётся первый топ-кандидат из последнего сохранённого отчёта. `--symbol` выбирает конкретную монету; `--report` позволяет указать ID другого отчёта из архива. Если топ пуст, монету нужно выбрать явно. SVG и PNG сохраняются в `output/coin-card/` под именем монеты; повторное превью той же монеты заменяет эти файлы, не меняя архив.

Пустой архив не подменяется демо-данными. Для проверки оформления без готового отчёта:

```sh
pnpm report:card --demo
```

Получатся `output/coin-card/DEMO.svg` и `output/coin-card/DEMO.png` с заметной пометкой о синтетических данных. Это не рыночный сигнал. Превью не подключено к пайплайну и ничего не отправляет в Telegram.

Время на карточке — закрытие последней свечи (`asOf + 1ч`), в МСК. Пропуски остаются пропусками; при отсутствии последней свечи старая цена не показывается как актуальная. Изменения цены и OI вычисляются по точным концам соответствующих окон, а относительный объём берётся из готовых признаков отчёта. Объём и OI на графиках — в базовом активе, не в долларах.

## Шаг 14 — Telegram-выпуск

Шаг автоматически запускается в `pnpm all` после сохранения отчёта шагом 13 и **отправляет один пост в Telegram**: карточки сверху, сводка и кандидаты снизу. Для отдельного запуска:

```sh
node src/step14-telegram.js
```

У шага нет флагов и альтернативных источников. Он читает `tmp/step13-report.json`, открывает указанный там сохранённый отчёт и собирает выпуск из уже готовых данных. Если результата шага 13 нет, запуск завершается ошибкой: другой отчёт или демонстрационные данные не подставляются.

Для отправки задайте локально в `.env`:

- `TELEGRAM_BOT_TOKEN` — токен бота от BotFather;
- `TELEGRAM_CHAT_ID` — ID чата или `@username` канала. Для канала боту нужны права на публикацию; для личного чата пользователь должен сначала написать боту.

Токен не добавляется в отчёт, манифест, запись отправки или логи. Текст и PNG передаются в Telegram; платная рассылка не включается.

В выпуске **не более 10 уникальных кандидатов и 10 картинок всего**, а не по 10 на раздел:

1. Топ агента — в исходном порядке `topRank`.
2. Дополнительные монеты с `socialSignificant: true` и `socialSentiment: "positive"`.
3. Дополнительные подтверждённые CoinGecko Trending из того же отчёта.

В двух дополнительных списках сначала идут более высокие оценки движения, при равенстве сохраняется порядок отчёта. Совпадения по символу или ID монеты не создают повторов; метки позитивного фона и CoinGecko остаются у выбранного кандидата. Обычные оценки вне этих групп не добираются ради количества. Число не вошедших в лимит показано в превью.

Текст содержит готовую новостную сводку со ссылками, объяснения кандидатов и контраргументы. Новая сводка — маркированный список из 3–5 новостей, до 250 символов с пробелами на пункт без учёта ссылок; при нехватке значимых событий пунктов меньше. Старые отчёты с абзацами и событиями остаются читаемыми. Сохраняются оговорки о неполных данных и неподтверждённых событиях; время новостей отделено от времени рыночного среза. Повторного анализа агентом нет.

Используется [`sendRichMessage`](https://core.telegram.org/bots/api#sendrichmessage): один rich-пост с коллажем карточек, либо одной фотографией, либо только текстом при пустом отборе. Это не классический альбом `sendMediaGroup`; лимиты подписи 1024 и обычного сообщения 4096 символов здесь не применяются. Rich-пост ограничен 32768 символами текста; превышение вызывает ошибку, а не скрытое разбиение выпуска. Наш лимит десять кандидатов сохраняется независимо от более высокого лимита вложений API.

Каждый запуск создаёт отдельную папку в `output/telegram-preview/`:

- `index.html` — офлайн-превью одного поста из того же HTML, с картинками сверху;
- `release.json` — манифест версии 2: `richMessage`, выбранные кандидаты и пути к картинкам;
- `cards/` — согласованные PNG-карточки и их SVG-оригиналы.

Точное отображение зависит от клиента Telegram и требует проверки пробным постом. Старые выпуски и архив не меняются. При отсутствии настроек отправки или ошибке API локальное превью и архив остаются доступны, но шаг завершается ошибкой. Ошибка шага 13 не запускает шаг 14. Синтетические выпуски не отправляются.

Каждый запуск шага отправляет новый пост, даже для уже опубликованного отчёта. Блокировки повторных и одновременных запусков нет. Результат последней успешной отправки хранится в `output/telegram-delivery/<ID отчёта>.json`: чат, статус и ID сообщения, без токена. Эта запись служит только для справки; старые записи удалять перед запуском не нужно.

Таймауты и неоднозначные ответы не повторяются автоматически. Перед новым запуском проверьте чат: предыдущий пост мог быть опубликован, а повторный запуск отправит ещё один. Только подтверждённый ответ 429 с ожиданием до 60 секунд допускает один автоматический повтор.

## Шаги

- **1. Список монет** — выбираем монеты с Binance USDT perpetual, исключаем стейблкоины и монеты с недоступными данными.
- **1.1. Описания монет** — добавляем описания новых монет со ссылками на проверенные источники.
- **2. История данных** — загружаем почасовые данные; монеты с неполной историей временно пропускаем.
- **3. Общий рынок** — загружаем капитализацию рынка и его основных сегментов.
- **3.1. Тренды CoinGecko** — получаем популярные монеты и категории, находим совпадения с нашим списком.
- **4. Признаки** — рассчитываем признаки раннего движения, устойчивую силу и рыночный фон.
- **5. Предварительный отбор** — оставляем кандидатов с ранними сигналами, исключаем уже зрелые движения.
- **6. Данные для агента** — собираем компактные профили отобранных монет.
- **7. Основной анализ** — GPT-6.1 Sol оценивает вероятность сильного движения без прогноза направления и выбирает до пяти монет.
- **8. Новости** — собираем свежие новости для топа агента и трендовых монет из основного отчёта.
- **9. Twitter** — собираем публикации за последние сутки для тех же монет.
- **10. Информационный фон** — Gemini 3.7 Flash дополняет объяснения новостями и обсуждениями, выделяет значимые инфоповоды.
- **11. Радар соседей** — независимо от основного отбора ищем монеты, отстающие от свежего роста прямых соседей.
- **12. Анализ радара** — GPT-6.1 Sol объясняет расхождения и выделяет наблюдения, заслуживающие внимания.
- **12.1. Короткая сводка рынка** — собираем общую криптоленту TradingView и поиск Twitter за последние 6 часов; Gemini 3.7 Flash выбирает 3–5 главных новостей по убыванию значимости, до 250 символов с пробелами на пункт и 1–2 источника на новость. При нехватке достойных событий пунктов меньше; веб-отчёт и Telegram показывают маркированный список.
- **13. Отчёт** — сохраняем основной анализ, сводку событий и радар соседей в архив для просмотра на сайте и скачивания одним HTML-файлом; передаём ID сохранённого отчёта следующему шагу.
- **14. Telegram-выпуск** — собираем текст и до десяти карточек из отчёта шага 13, сохраняем локальное превью и отправляем одним постом в Telegram.

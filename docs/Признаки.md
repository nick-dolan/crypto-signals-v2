# Признаки

Набор признаков для оценки `P(сильное движение в следующие 4–12 часов)` по каждой монете.

Признаки делятся на три роли. Агент интерпретирует их вместе: одиночный блок почти всегда шум.

| Роль | Смысл | Горизонт метрик |
|---|---|---|
| **Setup** | накопленное напряжение: сжатие, тихое накопление позиций | 24h–30d |
| **Trigger** | что изменилось прямо сейчас | 1h–4h |
| **Context** | режим рынка: возможно ли движение вообще | 12h–7d |

Рабочая гипотеза: сильное движение = высокий **Setup** + сработавший **Trigger** + непротиворечивый **Context**.

## Целевая переменная

```text
future_move = max(|close(t+k) / close(t) - 1|)  для k в [4h, 12h]
target      = future_move / (atr_24h(t) / close(t))
strong_move = target > 2.5
```

Нормировка на ATR обязательна: без неё весь сигнал уходит в низколиквидные монеты с постоянной тряской. Порог `2.5` стартовый, калибруем так, чтобы доля положительных примеров была примерно 10–15 %.

## Источники

Признаки считаются из часового слоя: OHLCV, Volume Delta, Open Interest, Funding Rate, Liquidations, Long/Short Accounts, Top Traders Positions, Premium, четыре social-метрики и рыночный контекст `CRYPTOCAP`.

Как именно эти ряды запрашиваются, какие у них study ID, как выбирается рынок и каково фактическое покрытие по монетам — в `docs/Сбор данных.md`. Полный каталог того, что вообще доступно — в `docs/Данные TradingView.md`.

Два правила влияют на сам набор признаков:

- у Volume Delta история всего около 69,4 дня, поэтому baseline для него считаем максимум за 30 дней и `z_90d` не строим;
- в итоговую вселенную входят только монеты с полным набором обязательных источников, поэтому все блоки признаков должны быть доступны по определению.

## Нормализация

Сырые значения между монетами несравнимы. Каждая метрика превращается в состояние относительно собственной истории:

- изменение за `1h / 4h / 12h / 24h`;
- скорость и ускорение изменения;
- rolling percentile за `30d / 90d`;
- z-score за `7d / 30d`;
- расстояние до rolling maximum и minimum;
- persistence — сколько часов подряд метрика держится выше порога.

Агенту отдаём только нормализованные значения. Сырыми оставляем лишь цену, market cap и объём в USD — как контекст масштаба.

## A. Сжатие волатильности — Setup

| Признак | Смысл |
|---|---|
| `rv_24h_over_rv_7d` | отношение realised volatility суток к неделе, ниже 1 — сжатие |
| `bb_bandwidth_pct_30d` | перцентиль ширины Bollinger Bands |
| `atr_pct_90d` | перцентиль ATR |
| `range_compression_streak` | часов подряд с диапазоном ниже медианы |
| `squeeze_age_hours` | длительность текущего сжатия |

`squeeze_age_hours` — ключевое поле блока: оно показывает зрелость накопленного напряжения.

## B. Объём и order flow — Trigger

| Признак | Смысл |
|---|---|
| `volume_z_30d` | всплеск объёма относительно нормы |
| `volume_acceleration_3h` | ускорение притока объёма |
| `rel_volume_at_time` | объём относительно того же часа суток |
| `vd_net_4h_over_volume` | направленность потока за 4 часа |
| `cvd_divergence_12h` | CVD растёт, цена стоит — скрытое накопление |

`rel_volume_at_time` обязателен: без поправки на час суток каждая смена торговой сессии даёт ложный всплеск.

`oi_up_while_rv_down` и `crowd_vs_top_traders` — самые ценные признаки блока: первый показывает накопление перед движением, второй — кто станет топливом.

## F. Ширина рынка и narrative — Context

| Признак | Смысл |
|---|---|
| `breadth_pct_universe_up_4h` | доля монет вселенной в плюсе |
| `segment_rotation_4h` | изменение долей BTC / ETH / alts / stables из `TOTAL*` |
| `category_momentum_4h` | медианное движение категории монеты |
| `category_breadth` | доля монет категории с одновременным ускорением |
| `coin_leads_category` | монета опережает свою категорию |
| `stablecap_change_24h` | медленный контекст ликвидности |

Категории берём из `crypto_categories` в Quote. `category_breadth` формализует распространение narrative по нескольким монетам. Пустой список категорий отмечаем как `not_applicable`, а категорию без трёх других монет — как `insufficient_peers`; саму монету в обоих случаях не исключаем.

## G. Расхождения

Готовые флаги, чтобы агент не выводил их самостоятельно. Пороги стартовые, подлежат калибровке.

| Флаг | Условие |
|---|---|
| `coiling` | сжатие + OI растёт + объём начинает расти |
| `attention_ahead` | social ускоряется, цена стоит |
| `unconfirmed_move` | цена растёт, OI и объём не подтверждают |
| `exhausted_hype` | внимание высокое, но активность замедляется и цена перестала реагировать |
| `laggard` | категория движется, монета отстаёт |
| `resilient` | BTC падает, монета держится |
| `squeeze_fuel` | экстремальный funding + высокий OI + однобокая толпа |

## Профиль монеты для агента

На выходе отдаём не весь массив, а компактный профиль:

- около 40 нормализованных полей, сгруппированных по блокам A–G;
- `top_triggers` — 3–5 полей с максимальным по модулю отклонением, с понятными подписями;
- `setup_score`, `trigger_score`, `context_score` — три агрегата.

Профиль формируется только при наличии всех обязательных источников. Если источник временно не пришёл в конкретном часовом цикле, профиль монеты за этот цикл пропускается: агент не должен прочитать отсутствие данных как отсутствие сигнала.

## Не входит в MVP

- on-chain и network — обновляются раз в сутки, для горизонта 4–12 часов бесполезны;
- ETF flows — только как дневной фон для BTC и ETH;
- AltRank и Galaxy Score — уже смешивают social с ценой, дают скрытую утечку;
- Volume Profile, Footprint и TPO — возвращают профили, а не простые ряды;
- bid/ask и размеры заявок — нет исторического backfill.
